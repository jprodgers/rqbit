# Interop harness: rqbit against qBittorrent and Transmission

Checks that rqbit's BitTorrent v2 and hybrid support works with other clients, not just with
itself. Everything runs on one machine: clients listen on 127.0.0.1 only, with DHT, local
discovery, peer exchange and port mapping off, and find each other through a small tracker the
script runs. No public swarm is touched.

## What you need

On Ubuntu 24.04:

```bash
apt-get install -y qbittorrent-nox transmission-daemon python3-libtorrent
```

That gives qBittorrent 4.6.3 (built on libtorrent 2.0.10), Transmission 4.0.5, and the
libtorrent 2.0.10 Python bindings for `/usr/bin/python3.12`, which the harness uses to make the
torrents qBittorrent's creator would make (qbittorrent-nox 4.6 cannot create torrents without its
GUI). Then build the two binaries under test:

```bash
cargo build --release -p rqbit
```

```bash
cargo build --release -p librqbit-create-torrent --example mktorrent
```

## Running it

```bash
python3 scripts/bep52/interop/interop.py --rqbit target/release/rqbit --mktorrent target/release/examples/mktorrent
```

Useful options: `--only 1a,3b` runs some scenarios; `--work DIR` (default `/tmp/bep52-interop`)
is where data, logs and the result go; `--store DIR` uses an existing folder as the large store
instead of generating one; `--store-total 2G` sets the size of the generated one.

A full run takes about 15 minutes and 8 GiB of disk. The result table is printed and written to
`<work>/matrix.md`; each client's log is in `<work>/logs`. The exit code is non-zero if any
scenario failed. "unsupported by peer" is not a failure: it records that the other client refused
something it does not implement.

## Scenarios

Two data sets are generated by `../make_store.py`: a small one (41 files, 200 MiB, 256 KiB
pieces) and one shaped like a JETCARP object store (`objects/sha256/ab/<64 hex>.parquet`, 201
files from 0 bytes to 300 MiB, 1 MiB pieces). Both include empty files and files one byte either
side of a block and of a piece. Every download is compared with the source byte for byte.

| # | What rqbit does | The other side |
| --- | --- | --- |
| 1a, 1b | Creates a hybrid / v2-only torrent with its own creator and seeds it | qBittorrent downloads |
| 1c | Seeds a hybrid torrent made by the `create_torrent` crate | qBittorrent and Transmission download |
| 1d | Its creator, the crate and libtorrent make the same hybrid torrent (same info hashes) | |
| 2a, 2b | Downloads a hybrid / v2-only torrent made by libtorrent 2.0 | qBittorrent seeds |
| 3a | Downloads a v2-only torrent from a `btmh` magnet link (piece layers by hash request) | qBittorrent seeds |
| 3b | Seeds a v2-only torrent | qBittorrent downloads from a `btmh` magnet link |
| 3c | Downloads a hybrid from a magnet link that has only the v2 hash | qBittorrent seeds |
| 4a | Downloads a hybrid whose only seed is v1-only | Transmission seeds |
| 4b | Seeds a hybrid to a v1-only and a v2 peer at once; must announce under both info hashes | Transmission and qBittorrent download |
| 4c | Downloads a hybrid from a v1-only and a v2 seed at once | Transmission and qBittorrent seed |
| 5a, 5b | Downloads a hybrid / v2-only torrent whose only seed has corrupted files, then a good seed joins | two qBittorrent seeds |
| 6a, 6b | Downloads only some files of a hybrid / v2-only torrent | qBittorrent seeds |
| 7a, 7b | Seeds an existing folder, is stopped and then killed, and must come back without hashing everything again; then serves it | qBittorrent downloads afterwards |
| 8a | JETCARP store: seeds the hybrid torrent; every file's `pieces root` matches `../bep52_ref.py` | qBittorrent downloads |
| 8b | JETCARP store: downloads the hybrid torrent | qBittorrent seeds |
| 9a | Nothing: a v2-only torrent is given to a v1-only client | Transmission |

## Things the harness had to learn

- **Transmission 4.0 treats BEP 47 padding files as real files.** It writes a `.pad` folder when
  it downloads a hybrid torrent, and it is not a complete seed unless those files exist. The
  harness gives a Transmission seed a hard-linked copy of the data with the padding files added.
- **libtorrent 2.0 and 2.1 ask for the end of a v2 file differently.** 2.0 (every qBittorrent
  release so far) treats a file's short last piece as a whole piece padded with zeros and asks for
  whole 16 KiB blocks; 2.1 asks only for the bytes that exist. `lt_download.py` puts a bare
  libtorrent of whichever version on the other end of rqbit to tell the two apart:

  ```bash
  /usr/bin/python3.12 scripts/bep52/interop/lt_download.py X.torrent /tmp/dl --peer 127.0.0.1:PORT
  ```

- qBittorrent needs `Session\MultiConnectionsPerIp=true` when several peers share 127.0.0.1, and
  `WebUI\LocalHostAuth=false` to be driven without a password.
